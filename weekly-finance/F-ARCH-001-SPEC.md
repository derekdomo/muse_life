# F-ARCH-001 财务看板新架构 · 纯合成口径与预览（2026-10-23 实现方交付）

所有者直提（2026-10-23）＋ PM 2026-10-23 19:01 细化方案。本文与同目录
`finance-arch.mjs` / `validate-finance-arch.mjs` 只用**纯合成数据**定义口径与
计算契约：不读真实账户、不写生产数据、不改银行账户/调度。生产写回 space-3
的通道仍需所有者另行裁决；裁决前只推进计算与呈现。

## 1. 总资产段：混合日期的最新已知净资产

- 主卡标题口径：「混合日期的最新已知净资产」，不称全账户银行实时。
- 每账户行保留三元组：来源提供的 `asOf`（余额时点）、实现方 `readAt`（读取
  时间）、覆盖标识 `coverage`（`plaid` 按日拉取 / `snapshot` 定期快照沿用）。
- 总卡同时给出两层日期范围（Plaid 层最新 asOf、快照层最旧 asOf）与缺失项
  清单；未知/缺失账户**不当 0**，列入 `missing` 并从总和中排除且明示。
- 负债按既定规则以正额展示、汇总时扣减。

## 2. 花销段：单一 spend 流（取消 fixed/flexible）

- 交易按稳定 ID 去重；`posted` 记入已发生 spend，`pending` 单列不重复计。
- 仅两项定义性排除（所有者已定）：本人账户间转账、贷款还本金。卡还款按
  转账匹配防双计。
- 退款以可追溯冲销行在同一交易流内抵减（保留原支出行与冲销行的配对 ID），
  不静默删除原支出；冲销行归属**原交易月份**，跨月差异在覆盖说明中列明。
- 无法拆分的贷款支付（本金+利息混合且无拆分依据）、未匹配转账：保留在
  `unclassified`，标「分类待确认／覆盖未完整」，不默默剔除、不伪造完整月。
- 当前月标「截至 YYYY-MM-DD」；不生成 fixed/flexible 或任何第三类分类。
- 生命周期归一（与输入顺序无关）：同 ID 精确重复行去重；posted 行
  取代同额同类同日的 pending 行（交易已入账）；其余同 ID 分歧列
  `conflicts`、不计数、月份不完整，绝不任挑一行。
- 统一 asOf 截点（PM 2026-10-24 01:07 细化）：先按截点定候选集、
  再做生命周期仲裁——晚于 asOf 的行不进入该 asOf 视图的仲裁（不
  只是改标题）：未来的 posted 行不能抹掉截点时点的 pending 状态，
  未来的同状态异额行也不能把过去已定的行打成冲突。冲突按作用域
  报告：冲突行所属月份、或该月有退款依赖该冲突 ID 时才列入该月
  `conflicts` 并使该月不完整；无关月份的冲突不污染本月。诚实边界：
  输入只有交易日期、没有来源观测时点时，本视图是「按交易日期的
  截点视图」，不声称重建来源在当时所知的全账快照。退款只抵减确实
  在 spend 流内的原交易（kind=spend、已入账、在截点内）；原交易不
  在样本、指向被排除类别或被冲突消解的退款列 `unappliedRefunds`、
  月份不完整，不静默消失、不单独造成负 spend。原始输入行永不修改。
- 覆盖契约（与 FIRE/异常共用）：只有 `coverageByMonth[月] === true`
  才算覆盖完整；`false`（不完整）与缺键/null（未知）分开列原因；
  覆盖未完整时金额只是已存小计（`amountBasis: stored-subtotal`），
  与已证实的真实 0 区分。分类完整与覆盖完整分列、两者皆备才称
  完整月。

## 3. FIRE 口径

- 只消费近 12 个**已结束自然月**中具有完整单一 spend 覆盖的同口径月份；
  缺月明确显示缺哪几个月，不用旧 flexible 口径或更早月份补成 12 个月，
  不年化当前 partial 月。网格固定为 throughMonth 之前 12 个自然月，
  逐格判定（缺行／不完整／同月冲突／覆盖不完整／覆盖未知逐格列
  原因），满 12 个唯一目标月全部完整才 `complete12`。

## 4. F0.6 / F1.6 与 Firance 分工（按 PM 19:01 建议登记，非跨仓决定）

- 旧 fixed/flexible 卡转为「历史对账存档」，不再与日常 spend 并排给两个
  花销答案；旧字段经合成映射表保留来源版本、日期与差异理由，旧数据不
  重算、不删旧行。
- F1.6 月度投资回报保留原资金流/端点覆盖要求；没有同窗依据即「未知」，
  不把日余额差称作收益。
- Firance 本体 `fixed_spend` 结构先作为原样存档来源；Life 日常 spend 按
  本条新口径独立呈现。此为建议边界，不宣称已修改 Firance 或所有者已
  裁决同步方案。

## 5. 异常机制 v0（候选阈值，未定案）

- 输入是**逐日事实**（`baselineDaily` / `currentDaily`），不是月总额：
  基准取最近 3 个可比完整月，每月取与当前月**实际同日窗**的逐日
  spend 累计（asOf 日序 1..D；月末读数时取该基准月的整月），基准值
  为 3 个同日窗累计的中位数。日支出中位数按同日窗内**真实逐日值**
  汇集计算，真实 0 日计入中位数；**缺日不是 0**，同日窗内有缺日的
  月份不可比。
- 基准月资格（PM 2026-10-24 01:07 细化）：先按**月份身份归一**——
  同月同值重复行只算一个月、同月冲突版本该月出局（无权威版本不
  任挑）；只取截至月**之前**的月份（当月与未来月不作基准）；每个
  基准月须有**其自身**的显式完整覆盖（条目自带 coverage 字段或
  `coverageByMonth` 中该月的条目，信号冲突出局），当前月的覆盖
  不能替代历史月。结果列明本次采用的 3 个基准月及各月覆盖；
  不足 3 个时 `insufficient` 附逐月出局原因。
- 月中/月末按 asOf 所在月的**实际天数**判定（28/29/30/31 天）：
  asOf 为当月最后一天才是 `month-end`，否则为 `mid-month-progress`，
  两种比较明确区分、不互相冒充。
- 触发候选：相对偏离 > 30% **且** 绝对偏离 > 日支出中位数 × 7
  → 列出异常类目与大额笔供下钻。
- 无逐日证据、可比完整月少于 3 个、当前同日窗内有缺日、基准为 0，
  或 coverage 不是明确完整（沿用同一覆盖契约：只有 `true` 算完整，
  `false` 与未知分开）时，一律只给 `insufficient` 与原因，不报
  「显著变动」。**不存在均匀摊分路径**：不许用月总额按天数比例
  缩放（如中位数 × 天数/30、日均 = 月总额/30）冒充逐日事实或日
  中位数；将来若引入估算试算，必须带明确「估算」标识且不得给
  出实际异常结论。该阈值仅供合成试算与讨论、仍未定案，不据此
  改真实预算/账户/外发。

## 7. 预览卡片模型（2026-10-23 21 时补，10-24 预览节点）

`buildArchPreview`（finance-arch.mjs）把上述三段契约组合成 10-25 计算/呈现
首片将渲染的卡片模型，仍为纯合成输入、零生产写入：

- 净资产主卡：混合日期总和＋Plaid/快照两层日期范围＋缺失清单分列。
- 花销卡：标题带「截至 YYYY-MM-DD」，正文固定三行——已发生 spend／
  待入账交易（未计入已发生）／覆盖缺口（未分类笔数与完整性），不出现
  fixed/flexible 或任何第三类花销答案；退款冲销配对随卡保留可追溯。
- FIRE 卡：合格完整月清单＋缺月清单。资格按 throughMonth 之前固定
  12 个自然月网格逐格判定（缺行／覆盖未知／不完整／同月重复冲突
  逐格列明原因），满 12 个唯一目标月全部完整才称「近 12 个完整月」，
  更早月份永不补格。
- 花销卡缺口行：分类完整（`classificationComplete`）与覆盖状态
  （`coverageStatus`：complete／incomplete／unknown）分列，两者皆
  完整才标完整；覆盖未完整时金额只是已存小计、与真实 0 区分。
  生命周期冲突（`conflicts`）与未抵减退款（`unappliedRefunds`）
  随卡列明，不静默消失。
- 截至日可重放（2026-10-24 03 时补，PM 01:07 产品推进）：同一份合成
  账本以不同 `asOfDate` 重放 `buildArchPreview` 必须确定性一致——同一
  交易（SYN-p）仅在截至日达到其 posted 日期时才从「待入账」行移入
  「已发生」行，截点之前保持 pending；重放不得修改输入账本。异常卡
  首列本次采用的 3 个唯一过去月份及各月覆盖状态，不足 3 个时直接
  给 `insufficient` 与已采用月份，不先亮正常/异常再把原因藏进下钻。
- 异常卡：`anomalyV0` 接受逐日事实（`baselineDaily` / `currentDaily`）
  与 `month` / `asOfDate` / `coverageStatus`，输出 `comparisonKind`
  ——`month-end` 仅当 asOf 是当月实际最后一天（按 28/29/30/31 天
  判定），否则 `mid-month-progress`；同时给出可比月清单、同日窗
  基准与日支出中位数。证据不足（无逐日数据／可比月 <3／缺日／
  覆盖非完整）时只显示 `insufficient` 与原因，不给显著标签，
  insufficient 时同样携带 `comparisonKind`，不把月中数冒充整月
  结论；卡面不出现任何均匀摊分估算冒充的事实数字。
