## 准确性和交付边界

本轮逐张查看全部首稿和修正版，检查动作方向、是否弯肘、支撑与接触点、阶段顺序、器械对应，拒绝原因逐项列于 rejected.json。AI多帧仍可能有轻微人物比例、光线、接触点和器械位置漂移；目前仅为可审候选，不能将“生成成功/哈希一致”当作动作或连续动画已验收。新图不替代原文字与视频解释。

- 当前生产组件 `ExerciseDemo.frames` 是固定两帧 tuple，`.frame-b` 仅做两帧 crossfade；不能只传入6个URL就宣称多帧已接通。Muse应加独立多帧类型/渲染分支，旧20项走原路径。
- 使用 manifest 的行列/索引顺序，真实显示中间帧，不能只取首尾。不得用数字像素插帧伪造关节轨迹。
- Y/T/W 与三向触点每行独立循环；三向触点中间行视角不同，不能跨行自动插值。提供阶段按钮与文字。
- 静蹲默认末帧静态，重播只进入一次然后停止。预览切换速度仅便于审图，不代表训练节奏或保持时长。
- 原图sheet的行列尺寸不一定整除（静蹲宽1997），裁帧时按真实像素边界分配余数，不能把相邻格线/人物带入。接入前在单帧尺寸下核对人体/器械完整、固定接触点配准；漂移不能通过拉伸人体“修复”，不合格帧仍须重做。
- 懒加载仅当前所需动作；不要把整个26MB review目录打包进产品。接入时只引入获批9项的选定素材，保留尺寸、压缩副本与原哈希关联。预备六项保持未引用。
- 减少动态效果默认静态，允许手动逐帧；暂停/播放、上一帧/下一帧和阶段状态用文字及边框，不能只靠颜色。关弹窗/页隐藏停止计时，切动作重置到该动作正确默认帧。
- 无YouTube iframe、远程缩略图或第三方脚本；原有已核实9条URL仅作外链，原文字与两处替代器械说明保留。
