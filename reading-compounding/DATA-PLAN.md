# Data Plan

## Context provenance
- `核心理念：复利指标是知识卡的复用而非阅读页数——片段→知识卡→实际复用才是利息；不打分、不 KPI 化、不惩罚断签` (verbatim build request; shapes the whole dashboard: reuse ledger is the core mechanism, no scores/streak-punishment UI)
- `预置第一本：《纳瓦尔宝典》（The Almanack of Naval Ravikant），来源=所有者自选，状态=想读，并注明「官方免费 EPUB 已暂存于所有者本地，待导入」——不得声称已导入全文` (verbatim build request; the ONE user-supplied seed row, seeded once via ensureSeeded on first owner read, exactly like space-10's preset skills — import_status stays 待导入， no full text claimed)
- `与学习复利分工：学习复利记广义输入→产出转化，读书复利记书籍来源的知识资产与其复用，两者不重复记账` (verbatim build request; no learning-input duplication in this app)
- `app 内对 snippet 直接提问（内置 agent 通道）是紧随其后的下一片（目标 10-24），本首片不做、不伪造答复` (verbatim build request; explicitly out of scope — no fake Q&A surface)
- Sibling artifact space-10 （学习复利） patterns reused: strict `ctx.viewer?.isOwner === true` gate before any DB touch with typed forbidden + zero-content responses, America/Los_Angeles day keys and streak helpers, and the immutable request-receipt ledger with payload hash + tombstones (CMP-LEARN-SAVE-001) as the model for this app's requestId ledger.
- User is color-weak (standing memory): status never rides on color alone — text labels, symbols (✓/●/▲/○), numbers and line styles carry meaning; Okabe-Ito palette.

## Tested sources
### ctx.inference (tag suggestions + think prompts)
**Used by**: suggestSnippetMeta action (suggested tags + one think prompt per snippet; suggestions are labeled 建议 and owner-editable, never auto-applied to the original text)
**Test command**: `bun /opt/muse/assets/spaces/ts-runtime/dist/probe-ctx.js < /tmp/probe-inference.ts` (snippet body: ctx.inference.complete with zod schema {tags: string[1..3], thinkPrompt: string})
**Sample output**: `{"tags":["自我成长","独立生活","摆脱期望"],"thinkPrompt":"你现在的生活选择，有多少是出于自己的意愿，又有多少是在迎合别人的期望？"}`
**Processing**: called only on explicit owner tap; result stored as suggestion fields on the snippet, visually separated from 原文 and owner 批注； failure → honest error, snippet still saves without suggestions.

### ctx.inference (per-snippet Q&A — CMP-READ-001 second slice, 2026-10-22)
**Used by**: askSnippetQuestion action — owner asks about ONE saved snippet; the server loads the stored snippet row and returns its 原文 + provenance （书名/版本/章节， chapter NULL → 章节不详） as a fixed snapshot alongside the answer, so the panel's pinned 「原文」 block is always the real stored text and never editable or merged with model output. The prompt forbids fabricating book content beyond the passage.
**Processing**: the exchange is ephemeral — turns live only in the panel's client state (history re-sent per ask, bounded to 6 turns), nothing is written on ask success OR failure (failure keeps the client-side question draft + retry entry; no half exchange, no half card). Only the owner's explicit tap on 「一键存为知识卡」 persists anything, through the existing createCard action and its request-key ledger (suggested core prefilled, labeled 建议， owner-editable; annotation is the owner's own words). Draft/deleted/missing snippets are typed notFound and never reach inference; non-owner/anonymous get typed forbidden with zero content, zero db access, zero inference calls. Validated by validate-reading-qa.mjs (57 checks, real handlers against an in-memory DB with a stubbed inference).

### Client-side EPUB parsing (no external host)
**Used by**: EPUB import flow + reader
**Test command**: inspected scaffold node_modules and SDK dist — no zip library is bundled (checked package.json deps and node_modules listing); SDK client exports `fileToBase64`/`bytesToBase64` helpers for moving file bytes through action args.
**Sample output**: SDK `client/file-encoding.d.ts` confirms `fileToBase64(file) → { dataBase64, mimeType }`.
**Processing**: import is fully client-side: a hand-written minimal ZIP reader (EOCD/central directory, store + deflate via the browser's native `DecompressionStream('deflate-raw')`) unpacks the EPUB in the browser; container.xml → OPF manifest/spine → per-chapter XHTML sanitized with DOMParser (scripts, event handlers, remote images/links stripped; remote resources never fetched). Sanitized chapter HTML + TOC are stored in this app's private DB (book_chapters.text) via chunked save actions; the original EPUB bytes are also uploaded (base64, chunked) and kept with ctx.blobs under `epub/<bookId>` so a failed import keeps the original file and can be retried against the same book row (no duplicate book). Nothing is uploaded to any external service; no book full text is fetched from any website — commercial books enter only as owner-supplied files. If DecompressionStream is unavailable, import fails honestly with status 失败 and the original file/blob + reading position preserved.

### 微信读书片段 (paste / screenshot OCR)
**Used by**: snippet draft intake
**Processing**: paste path is plain text entry into a pending draft. Screenshot path: owner picks an image in the app; the image goes through ctx.inference with an images input (SDK InferenceImageInput, probed schema path above) to extract candidate text into the SAME pending-draft state — never directly into snippets. Owner must confirm/edit text + book + chapter before it becomes a snippet, stamped source=粘贴 or OCR. No WeRead cookie, no unofficial scraping (explicitly excluded by the brief).

## Web-search sources
None. No web content is fetched; book text comes only from owner-supplied files.

## Agent-task sources
None. recordKnowledgeCardFromChat / recordCardReuse are plain owner-gated actions the main agent invokes when delivering chat work; they need no spawnTask.

## Long-term data behavior
- **Refresh policy**: none — no cron, no external feeds. All data is owner-entered or derived from the owner's own rows at read time.
- **Growth**: books, reading sessions, snippets, knowledge cards, reuse entries, tags — all append-oriented; deletes are soft (deleted_at) so tombstones and the request ledger keep working and deleted snippets never resurface in 片刻回味.
- **Ordering**: dashboard aggregates server-side; cumulative knowledge-card curve buckets cards by the LA calendar day of their real created_at (first save), never backfilled; reuse counts are separate columns (cards total / distinct cards reused ≥1 / total reuse events) per the brief's example (2 cards, 3 uses → 2 / 2 / 3).
- **Time semantics**: reading streak counts only explicit reading-session rows' LA local days; imports, savor views, and internalized marks never create reading days or minutes. Unknown totals stay unknown: progress keeps the owner's original unit （页/章）, no percentage is fabricated when total pages are unknown; unknown duration is NULL, distinct from 0.
- **Save safety (A-class)**: every mutating save carries a client-generated requestId recorded in an immutable request_keys ledger (request_id PK, payload fingerprint hash, result row id, tombstone deleted flag — never deleted, never rewritten except stamping deletion). Same key + same payload → original row returned; same key + different payload → typed conflict, draft preserved client-side; retry after delete → typed deleted, never resurrects. Edits use optimistic version checks: stale-version saves return conflict and keep the newer row.
- **Atomicity hardening (CMP-READ-SAVE-001 fix, 2026-10-22)**: the ledger pattern above was originally implemented as sequential statements (claim → insert body → insert ledger), which the PM reproduced as four failures (orphan body row on ledger failure; duplicate on same-key race; false "replayed" after a half-applied delete; a snippet fingerprint that omitted chapterLabel). Now every create path (book/session/import-book/snippet/draft/card/chat-card/reuse) commits its ENTIRE write set — body row(s), provenance snippet, tag rows, ledger row, the ledger's result-id backfill, and side effects like the book progress marker — as ONE `db.batch` (a single atomic unit; verified by probe: a trigger-aborted statement rolls back the whole batch, and a same-key race loses on the ledger PK with the body rolled back too). Fingerprints cover all stored content AND provenance (chapterLabel included), normalized exactly as stored. Replay/deleted arbitration reads the persisted ledger AND the created row's own `deleted_at` visibility (a reuse dies with its card), so even rows deleted before this fix answer "deleted" truthfully. Deletes commit the soft-delete + tombstone stamp in one batch. createCard takes provenance only from a confirmed, live snippet — missing/draft/deleted snippet ids are typed notFound and never lend a source label. No schema change, no migration, no production data touched; validated by validate-save-atomicity.mjs (113 checks incl. the four PM repros with injected trigger failures, same-key concurrency, per-write-point failure injection, legacy no-ledger rows) plus validate-reading-qa.mjs 57/57 unchanged.
- **Import generation / original-key protection (CMP-READ-IMPORT-001 fix, 2026-10-22)**: the existing-book import path originally skipped the request ledger entirely — a replayed beginImport deleted the book's chapters and flipped it back to "processing", destroying a finished import (PM-reproduced). Now an import is a generation identified by its beginImport requestId, bound through uploadImportFile / saveImportChapters / finishImport via `importId`. beginImport arbitrates through the ledger on BOTH paths (fingerprint: new book = title/author/source/versionLabel; existing book = existingBookId + versionLabel), so same-key replays return the original result with zero writes and same-key/different-payload is a typed conflict. A fresh begin only claims the staging area (migration 0004: `books.import_gen`, `books.import_blob_key`, `import_staged_chapters` with a unique (book_id, gen, idx) index): chapters stage in isolation, the original file stages at `epub-stage/<bookId>/<gen>`, and readers keep seeing the live chapters + live blob pointer. finishImport validates the staged generation (contiguous idx 0..n−1 and, when reported, an exact chapterCount match) and promotes it in ONE generation-guarded db.batch (delete live, insert-select staged in, flip blob pointer, ready, reset position); a failed finish changes only the status. Late writes from a superseded generation are typed conflicts with zero DB/blob writes; duplicate idx within/across chunks upserts one staged row (last wins); soft-deleted books answer deleted/notFound and never resurrect. Legacy compatibility: books with import_gen NULL keep the historical direct-write path, unbound (no-importId) writes bind to the book's current generation when one exists, and bound writes against a generation that no longer owns the book are explicitly refused (typed conflict) rather than silently applied. Client mints a fresh key per import attempt (the old stable `retry-<bookId>` key is gone). No production data touched; validated by validate-import-generations.mjs (69 checks, real handlers + in-memory migrated DB + synthetic blob store) with validate-save-atomicity.mjs 123/123 and validate-reading-qa.mjs 64/64 unchanged.
- **Pinned discussion citation (CMP-READ-001 closure, 2026-10-22)**: every successful askSnippetQuestion response now CONSUMES and RETURNS the binding of exactly that ask — the questionRequestId it was sent with (echoed verbatim), the snippet id, the snippet version actually read, and the response-time sourceText/sourceLabel snapshot. The client pins all of it on the turn: 「查看本次原文」 renders the turn's own snapshot (never re-read from the library, so a library update cannot graft an old answer onto a newer source), editing the question text rotates to a fresh questionRequestId (a retry of unchanged text reuses it), and a response is applied only while it is still the in-flight ask with the matching consumed id — a late/superseded response adds no turn and never clears an edited draft. A card is now distilled per turn （整理这轮为卡）: only that turn's suggestion enters the editable draft, with 「我的一句话结论」 and 「我的批注」 kept apart, and the turn's pinned citation shown as the draft's fixed source. Binding scheme (A-class, migration 0005): four nullable columns on knowledge_cards — qa_question_request_id, qa_snippet_version, qa_source_text, qa_source_label (NULL for cards not made from a Q&A turn). createCard accepts the binding as optional args, includes it in the payload fingerprint, and RE-VERIFIES it against the stored snippet row before writing (version + verbatim text + rebuilt label must all match; a partial binding, a binding without its snippet, or a tampered snapshot is a typed conflict with zero writes and the save key NOT consumed). If the source moved since the discussion, the save conflicts; the panel keeps the draft, shows 「原讨论来源已更新」 with the old pinned citation and the current snippet side by side, and only the owner's explicit tap （改用当前片段出处保存） re-bases the binding on the current row — never silently. Stored citations are immutable: later snippet edits/version bumps never rewrite a card's qa_* fields, and the receipt + cards tab read the citation back from the actual stored card row （查看当次讨论引用）. No reuse/TIME/coins side effects: asking, distilling, and viewing citations write nothing and register nothing; recordCardReuse remains the only reuse path, confirm-first as before. Validated by validate-reading-qa.mjs (107 checks incl. two turns with distinct citations, failure-then-retry under the original id, edited-question new id, stale-version ask refusal, moved/deleted source saves, partial/tampered bindings, old-key replay, library-refresh immutability, exact reuse counts) with validate-save-atomicity.mjs 123/123 and validate-import-generations.mjs 69/69 unchanged; production data untouched (synthetic in-memory DB only). Rollback: drop the four qa_* columns (migration is additive/nullable; older code ignores them) and revert the panel to the shared draft form.
- **Locatable receipt (CMP-READ-001 continuation, 2026-10-22)**: after a Q&A-panel card save, the panel keeps the server's actual cardId + the snippet id and shows a receipt — 「已保存」/「原键已保存」, the stored row's core and 出处 read back from the library, 「查看这张卡」 (jumps to the cards tab, scrolls to and highlights that exact card id; a missing card is named as deleted there) and 「回到原片段」. A failed read-back shows 「已保存，详情暂未读出」 with a read-only refetch retry — it never re-creates under a new key; a card deleted since is stated plainly and never rebuilt from the model answer; a payload conflict keeps the current inputs and surfaces the authoritative stored card. Asks carry a per-question questionRequestId (retries reuse it) and the pinned snippet's version — a stale version is refused with zero inference. Reuse registration keeps its existing confirm-first form (no prefilled scene); success locates the actual event by its real reuseId in the card's event list, and a lost response continues on the original key so the replay locates the original event.
- **ACL**: every action checks `ctx.viewer?.isOwner === true` before any DB read/write or seed; non-owner/anonymous get typed forbidden responses with zero content and zero writes. No L0.1 exception in this app.

## Rejected approaches
- **Tried**: server-side EPUB parsing or fetching book text
  **Why rejected**: brief mandates browser-side parsing, private runtime storage only, and forbids downloading commercial full text from any site.
- **Tried**: adding a zip dependency (jszip/fflate)
  **Why rejected**: not in the scaffold's pinned dependency set and no install step is guaranteed; the native DecompressionStream ZIP reader covers store+deflate EPUBs with an honest failure state otherwise.
- **Tried**: WeRead API/cookie integration for shelf + highlights
  **Why rejected**: explicitly forbidden by the brief; shelf enters by screenshot/口述 as booklist-only rows, highlights via paste/OCR drafts pending owner confirmation.
